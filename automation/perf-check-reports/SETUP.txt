===============================================================================
 PERF CHECK REPORTS - SETUP
 3 VMs x 3 instances (MARSDBW1-3 \ MARS01-03), Always On AGs.
 Every instance saves its own check in DBAdmin; ONE collector job on
 MARSDBW1\MARS01 sends one email with one HTML report per VM.
 Files: automation/perf-check-reports
   HealthPerfCheck_AgentJob.sql   (SQL side: PART 1-3)
   Create_PerfCheck_Logins.sql    (logins)
   Collect-PerfCheckReports.ps1   (collector)
   database_mail_setup.sql        (Database Mail on the coordinator)
===============================================================================

Accounts - no Windows password is needed anywhere:
  - job owner (sa) ............... runs the check on each instance, locally
  - SQL login dba_perfcheck ...... ONLY reads DBAdmin.dbo.DBA_PerfCheck_Report
  - SQL Agent service account .... of MARSDBW1\MARS01: runs the collector,
                                   writes the files, sends the email
  - your admin account ........... one-time setup only (CyberArk RDP, then
                                   "Run as different user" / secondary logon)

-------------------------------------------------------------------------------
 1. ON ALL 9 INSTANCES - PART 1 (procedure + table in DBAdmin)
-------------------------------------------------------------------------------
DBAdmin exists on every instance and is NOT in an availability group.
Open HealthPerfCheck_AgentJob.sql, run PART 1 (down to the "PART 1 done" check).
Test it once by hand on one instance:

    EXEC DBAdmin.dbo.usp_DBA_HealthPerfCheck @SampleSec = 10, @DurationMin = 1,
         @SendEmail = 0, @SaveToTable = 1, @PrimaryOnly = 1;
    SELECT TOP (5) run_id, run_start, run_end, status, ag_roles, error_message
    FROM DBAdmin.dbo.DBA_PerfCheck_Report ORDER BY run_id DESC;

-------------------------------------------------------------------------------
 2. ON ALL 9 INSTANCES - PART 2 (the check job)
-------------------------------------------------------------------------------
Set at the top of PART 2 and run it - the SAME @StartTime everywhere:
    @SampleSec   = 30
    @DurationMin = 5
    @StartTime   = '06:00'
It creates "DBA - Health & Performance Check" (owner sa). It saves to the table
and sends no email. Secondary-only instances save a SKIPPED row and stop.

-------------------------------------------------------------------------------
 3. ON ALL 9 INSTANCES - Create_PerfCheck_Logins.sql SECTION A (the reader login)
-------------------------------------------------------------------------------
The instances must allow SQL authentication:

    SELECT SERVERPROPERTY('IsIntegratedSecurityOnly');   -- 0 = mixed mode

Type the password in @Password, run SECTION A, then REMOVE the password from
the file (don't save it). Use the same password on all 9 instances.
dba_perfcheck gets SELECT on DBAdmin.dbo.DBA_PerfCheck_Report and nothing else.
It ends by listing what the login can do (should be CONNECT SQL + SELECT on the table).
(Existing dba_perfcheck login from the older version: SECTION C has the REVOKE
 lines to remove the rights it no longer needs.)

-------------------------------------------------------------------------------
 4. ON MARSDBW1 ONLY - files, folder rights, Database Mail
-------------------------------------------------------------------------------
a) Copy Collect-PerfCheckReports.ps1 to C:\DBA\PerfCheck on MARSDBW1.
b) In its $Config (top of the file) check:
       Instances    = the 9 instances (already filled in)
       Recipients   = 'dba-team@yourcompany.com'   (and CopyRecipients)
       MailInstance = 'MARSDBW1\MARS01'
       MailProfile  = ''   (default public profile) or the profile name
c) The Agent service account of MARSDBW1\MARS01:

       SELECT servicename, service_account FROM sys.dm_server_services;

   usually NT SERVICE\SQLAgent$MARS01. Give it Modify on the folder:

       icacls "C:\DBA\PerfCheck" /grant "NT SERVICE\SQLAgent$MARS01:(OI)(CI)M"

d) Database Mail on MARSDBW1\MARS01: run database_mail_setup.sql with
   @MaxFileSizeMB = 10 (a report with 3 instances can be bigger than the default
   limit of about 1 MB). The Agent service account normally already has a login
   there (sysadmin). Check:

       SELECT name, IS_SRVROLEMEMBER('sysadmin', name) AS is_sysadmin
       FROM sys.server_principals WHERE name LIKE N'NT SERVICE\SQL%Agent%';

   Or simply run Create_PerfCheck_Logins.sql SECTION B on MARSDBW1\MARS01: it
   checks this and, if needed, gives the account msdb DatabaseMailUserRole.

-------------------------------------------------------------------------------
 5. ON MARSDBW1 - HAND THE dba_perfcheck PASSWORD TO THE COLLECTOR (one-time)
-------------------------------------------------------------------------------
Command prompt with secondary logon (your admin account):

    cd /d C:\DBA\PerfCheck
    powershell -ExecutionPolicy Bypass -File .\Collect-PerfCheckReports.ps1 -SaveCredentialFor "NT SERVICE\SQLAgent$MARS01"

It asks for the dba_perfcheck password once and writes a hand-over file only
Administrators, SYSTEM and the Agent service account can read. The collector's
first run re-encrypts it so that ONLY the Agent service account can decrypt it
(Windows DPAPI, this machine only) and deletes the hand-over file. The password
is only ever decrypted into memory - never written to a connection string, the
log or job history.
Change it later: Create_PerfCheck_Logins.sql SECTION C (ALTER LOGIN on all 9),
delete PerfCheck.NT_SERVICE_SQLAgent$MARS01.cred, then run this step again.

Optional manual test as your own account (asks for the password, answer N to
"Save it"): after a check job has run on all 9 instances,

    powershell -ExecutionPolicy Bypass -File .\Collect-PerfCheckReports.ps1

-------------------------------------------------------------------------------
 6. ON MARSDBW1\MARS01 ONLY - PART 3 (the collector job)
-------------------------------------------------------------------------------
Set at the top of PART 3 and run it:
    @ScriptPath = N'C:\DBA\PerfCheck\Collect-PerfCheckReports.ps1'
    @StartTime  = '06:10'      (10 min after the check job)
It creates "DBA - Perf Check Reports (collector)": CmdExec, no proxy, owner sa.

-------------------------------------------------------------------------------
 7. FIRST RUN
-------------------------------------------------------------------------------
Start the check job on all 9 instances (or wait for 06:00), then about 8
minutes later the collector:

    EXEC msdb.dbo.sp_start_job @job_name = N'DBA - Health & Performance Check';     -- each instance
    EXEC msdb.dbo.sp_start_job @job_name = N'DBA - Perf Check Reports (collector)'; -- MARSDBW1\MARS01

Expect ONE email with 3 attachments (MARSDBW1_PERF_..., MARSDBW2_..., MARSDBW3_...).
Secondary-only instances are listed as SKIPPED; AG tables show only primary AGs.
Where to look on MARSDBW1:
  - SQL Agent job history
  - C:\DBA\PerfCheck\CollectorJob_output.txt   (last collector output)
  - C:\DBA\PerfCheck\Logs\                     (collector log per run)
  - C:\DBA\PerfCheck\Reports\                  (the .html files)
On every instance, nothing left behind after a run:

    SELECT value_in_use FROM sys.configurations WHERE name = 'blocked process threshold (s)';
    SELECT name FROM sys.dm_xe_sessions WHERE name = 'DBA_PerfCheckJob';   -- no rows

-------------------------------------------------------------------------------
 IF SOMETHING GOES WRONG
-------------------------------------------------------------------------------
An instance shows NO DATA / RUNNING
    -> its check job didn't run / is still running: job history on that instance,
       and @StartTime of both jobs (the collector waits up to 15 min).
An instance shows FAILED
    -> the email shows the error; also job history on that instance and
       error_message in DBAdmin.dbo.DBA_PerfCheck_Report.
An instance shows UNREACHABLE
    -> dba_perfcheck missing / wrong password / mixed mode off, or firewall /
       SQL Browser (named instances) between MARSDBW1 and that VM.
Collector fails at once: "No saved SQL login for NT SERVICE\..."
    -> step 5 not done, or for another account name than the one the job runs as.
Email has no attachments
    -> the collector log says why: usually a file above MaxFileSize (step 4d).
Collector job fails with exit code 3 or 4
    -> newest file in C:\DBA\PerfCheck\Logs\ (3 = script error, 4 = no email sent).
